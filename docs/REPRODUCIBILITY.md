# Reproducibility and release verification

This artifact is self-contained and uses exact rational arithmetic from the Python standard library. It does not download data, call a model API, require a GPU, or depend on a package registry.

## Supported runtime

- CPython 3.10 or newer.
- A POSIX/Linux host is required by the CLI process limits, campaign process-group
  termination, and `resource` accounting. Native Windows can use the pure-library
  analysis and replay functions, but does not support the complete supplied runner.
- The retained validation was executed with one worker and deterministic seeds.

Original rational parameters retain the 16,384-bit admission limit. Derived
coefficients, supports, budgets and witness coordinates use chunked exact decimal
parsing and formatting, without reapplying that original-input limit. The CLI
also uses chunked conversion for JSON integer inputs and certificate indices;
interpreter-wide decimal-conversion safeguards are unchanged. Its existing file,
CPU and memory limits still apply, so successful completion is not promised for
every admitted program.

The three small exact-I/O regressions use owned rational programs and a mocked
unavailable ordinary formatter, rather than boundary-sized inputs. Their run is
separate from retained campaign and clean-copy validation records:

```bash
python -B -m unittest discover -s tests -p test_exact_pipeline.py -v
```

## One-command scientific replay

```bash
export PYTHONHASHSEED=0
export PYTHONDONTWRITEBYTECODE=1
export OMP_NUM_THREADS=1
export OPENBLAS_NUM_THREADS=1
python run_all.py
```

`run_all.py` returns nonzero on any failed unit test, oracle comparison, certificate replay, timeout, or deterministic-result comparison. It also sets `PYTHONDONTWRITEBYTECODE=1` for every child process so the documented replay does not create caches rejected by release integrity checking. The explicit commands remain documented in the main README and status records.

## Distribution integrity

```bash
python verify_release.py --integrity-only
python verify_release.py --run
```

The first command verifies the immutable-file manifest, path safety, required files, Python syntax, and absence of packaged caches. The second performs those checks, runs the full scientific replay with bytecode writes disabled, and repeats the integrity check afterward. The manifest deliberately excludes generated result files, logs, bytecode caches, and the manifest itself; those outputs may be regenerated by the replay.

## Evidence boundary

The executable checks support the implementation and the finite validation claims. They are not a proof-assistant certification of the general mathematical theorems. The paper supplies the written proofs and states the frozen semantic assumptions and exclusions.
